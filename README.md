### Чем занимаюсь

Строю системы, которые работают без меня: принимают деньги, ведут учёт, чинят себя по расписанию и присылают отчёт, когда что-то идёт не так.

Специализация — **асинхронные Telegram-сервисы с реальной бизнес-логикой**: биллинг, подписки, тикет-системы, корпоративный учёт. Это не боты-визитки — это продакшен с транзакциями, миграциями и живыми пользователями.

Отдельное направление — **суверенная сетевая инфраструктура**: распределённые VPN-трассы, маршрутизация трафика, администрирование узлов.

За последний год к этому добавились ещё три линии работ:

- **Embedded и IoT** — прошивки ESP32 и хаб на Raspberry Pi для B2B-игровой системы: протокол на радиоканале, расчёт на краю сети, работа при потерянной связи с сервером.
- **Медиа-инфраструктура** — приём и раздача видеопотока с низкой задержкой, WebRTC-голосовая, авторизация эфира на уровне nginx.
- **Обследование объектов и миграции** — инвентаризация сетей и видеонаблюдения на действующей площадке, перенос легаси-CMS с сохранением поисковых позиций.

**Экспертиза:**

- **Асинхронный Python** — aiogram 3, asyncio, пулы соединений, фоновые задачи на APScheduler
- **Проектирование БД** — нормализация под реальную предметную область, идемпотентные миграции, транзакционная целостность на уровне СУБД (`SELECT ... FOR UPDATE`), а не на уровне договорённостей в коде
- **Биллинг и подписки** — платёжные потоки с ручной модерацией, компенсирующие откаты при отказе внешнего API, скидки, промокоды, реферальные программы, акты сверки
- **Сетевая инфраструктура** — Marzban / Xray, VLESS + Reality, схема «входной узел РФ → выходной узел ЕС», мониторинг живости трассы
- **DevOps** — Docker Compose, healthcheck-зависимости между сервисами, автобэкапы с ротацией, деплой и сопровождение на bare-metal
- **Embedded и радиопротоколы** — единый машиночитаемый контракт протокола, из которого генерируются константы для Python и заголовки для C++; расхождение реализаций ловится golden-векторами в CI, а не на площадке
- **Медиа-стек** — SRT вместо RTMP на нестабильном канале, HLS и WHEP для просмотра, авторизация эфира через `auth_request` в nginx, mesh-голосовая на WebRTC с собственным TURN
- **Обход блокировок** — маршрутизация по SNI на одном порту, постоянный туннель вместо трансграничного соединения на каждого клиента, смена домена без обрыва живых сессий
- **Обследование и документация** — инвентаризация ЛВС и видеонаблюдения, коммерческие предложения по этапам, служебные записки и отчётность в документообороте заказчика

#### 🛡 Tech Poly VPN

**Telegram-биллинг поверх Marzban.**

Полный жизненный цикл платного VPN-доступа: от заявки на оплату до ежемесячного акта сверки с корпоративным клиентом. Marzban управляет трафиком, бот — источник истины по деньгам и срокам.

- Атомарное подтверждение платежа через блокировку строки — двойное начисление невозможно даже при одновременной работе двух админов
- Компенсирующий откат, если панель не ответила после списания
- Динамические цены по группам, промокоды, реферальные скидки
- Корпоративный контур: реселлеры, ключи для сотрудников без привязки к Telegram, append-only журнал начислений
- Резервная выдача конфигов через VK, если Telegram недоступен
- Мониторинг трассы, автобэкапы, акты по расписанию

`Python` `aiogram 3` `MariaDB` `Marzban API` `APScheduler` `Docker`

#### 🎫 Help Desk Bunker

**Тикет-система для внутреннего IT-отдела.**

Превращает Telegram в полноценный хелпдеск: структурированные заявки, маршрутизация в чат отдела, двусторонняя переписка, отчётность для руководства.

- Семь статусов с явными переходами; **закрытие подтверждает пользователь, а не исполнитель**
- Карточка заявки редактируется на месте — в чате не растёт лента дублей
- Reply-переписка с маппингом в БД, переживающим рестарт сервиса
- Договорённость о времени визита прямо в карточке
- Оценка работы 1–10 с защитой от промаха
- Автоматика: напоминания о «зависших» заявках, CSV-отчёт 1-го числа, еженедельный дамп БД

`Python` `aiogram 3` `SQLAlchemy 2.0 async` `Alembic` `MariaDB` `Docker`

#### 🔫 Phygital Лазертаг

**B2B-система для парков: прошивки, хаб и админка инструктора.**

Тагер и повязка на ESP32, хаб на Raspberry Pi 5. Урон считается на краю сети: повязка сама вычитает HP и сама шлёт стрелку хитмаркер, хаб только агрегирует события. Игра не останавливается, если связь с хабом пропала.

- Единый источник правды — `protocol.yaml`, из него генерируются константы для Python и заголовок для C++
- Python — эталон, C++ обязан совпадать бит в бит; сверка golden-векторами в CI на каждый коммит
- Прошивка на весь парк одна: номер комплекта привязывается в админке по MAC и уезжает в NVS, сгоревшая плата меняется без пересборки
- Симулятор парка позволяет отладить всю игровую логику до сборки физических прототипов
- LoRa 433 МГц — аварийные команды в обход WiFi
- Брокер без анонимных подключений: права на топики генерируются из контракта

`ESP32-S3 / C3` `C++` `ESP-NOW` `ИК MilesTag II` `MQTT` `FastAPI` `PostgreSQL` `Redis` `TypeScript` `LoRa`

#### 📡 ToshaStream

**Личный стрим-сервер с голосовой связью.**

Замена голому `nginx-rtmp`, который рвал трансляцию и пускал любого, кто знал IP. Поток идёт по SRT поверх UDP с переспросом потерь, два качества одновременно — родное 3440×1440 и облегчённое для мобильного интернета.

- Просмотр в браузере через HLS, с низкой задержкой через WHEP, в VLC через RTSP и SRT
- Эфир закрыт проверкой сессии на уровне nginx (`auth_request`), для VLC — отдельный секрет
- Три текстовых чата с историей, счётчиком непрочитанного и оверлеем для OBS
- Голосовая на WebRTC-mesh со своим TURN: голос через сервер не идёт вовсе
- Чат поверх игры отдельным окном системы (Document PiP)
- Видео на сервере не перекодируется — оба качества кодирует видеокарта на ПК
- Управление аккаунтами вынесено в отдельный Telegram-бот через внутренний API

`Go` `MediaMTX` `SRT / HLS / WHEP` `WebRTC` `coturn` `SQLite` `nginx` `Docker`

#### 🔓 UNLOCK — интерактивные открытки

**Сервис, который делает из ссылки маленькую историю.**

Получатель попадает не на открытку, а в закрытый терминал: нужен пароль. Забыл — включается Recovery Protocol с личными вопросами. Ввёл верно — терминал расцветает в тему, и дальше три экрана, где получатель сам собирает вечер. Выбор прилетает владельцу в Telegram.

- Одна установка обслуживает сколько угодно открыток: свой адрес, тема, тексты, меню и история заявок у каждой
- Всё правится из Telegram-бота кнопками — без правки кода и деплоя
- Сайт — один HTML-файл без сборки и зависимостей, наружу не ходит вообще
- База без порта наружу: видна только сервису

`Python` `aiohttp` `aiogram 3` `PostgreSQL` `Docker`

<td width="50%" valign="top">

#### 🎧 ToshaMusic

**Выгрузка музыки в Hi-Res с проверкой, что это правда Hi-Res.**

Принимает ссылку Qobuz, Deezer или Tidal и отдаёт файлы в максимальном доступном качестве — до FLAC 24 bit / 192 kHz. Ключевое — жёсткая верификация: имя, теги и подпись формируются по фактическим параметрам аудиопотока, а не по обещаниям API стриминга.

- `ffprobe` и `mutagen` измеряют разрядность, частоту дискретизации и частоту среза спектра
- Расхождение с заявленным честно пишется в чат — ловит и CD-мастер под видом 24/192, и «псевдо-lossless» из MP3
- Очередь с ограничением параллелизма: защита от бана аккаунта стриминга
- Локальный Bot API — файлы до 2 ГБ
- Мягкая деградация: если API источника молчит, карточка всё равно показывается

`Python` `aiogram 3` `FFmpeg` `mutagen` `Local Bot API` `Docker`
